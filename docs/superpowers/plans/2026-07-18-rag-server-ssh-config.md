# RAG 专用服务器本机 SSH 配置计划

## 目标

将新服务器 `103.205.240.84` 作为 RAG 专用服务器登记到本机 SSH Config 与项目本地 `codex.md`，并验证 SSH 配置可解析、服务器可连接。

## 执行前约束

- 默认使用 `root:22` 尝试连接；若服务器拒绝，再根据真实返回调整，不猜测其他用户或端口。
- `~/.ssh/config` 只保存主机、用户和连接参数。OpenSSH Config 不支持明文密码字段，密码只记录在按项目规范禁止提交的本地 `codex.md`。
- 不把密码写入计划、源码、日志或 Git 提交；不上传项目文件，不在新服务器安装或修改任何 RAG 组件。
- 保留现有 SSH Host，不覆盖用户已有配置；项目现有日志和未跟踪资料不暂存、不提交。

## 执行计划

1. 在 `~/.ssh/config` 新增独立别名 `RAG-Server`，指向 `103.205.240.84`、`root`、22 端口，不复用未经验证的旧服务器身份文件。
2. 在本地 `codex.md` 的服务器章节增加 RAG 专用服务器定位、连接命令和本地 SSH 登录凭据，并明确其与现有业务中间件服务器隔离。
3. 使用 `ssh -G RAG-Server` 验证最终解析配置，再通过密码进行一次只读连接，采集 hostname、系统和基础资源信息，不修改远端。
4. 将实际修改、验证结果和限制追加到本计划；检查 Git 状态，确保密码与 `codex.md` 不进入提交，只提交不含凭据的计划记录。
