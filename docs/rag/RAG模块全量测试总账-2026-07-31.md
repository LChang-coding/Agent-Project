# RAG 模块全量测试总账

> 生成日期：2026-07-31
>
> 统计原则：只采用已落盘的 manifest、JSONL、metrics、数据库回读与服务器采样；失败、未完成和探索性运行不混入正式结论。
> 安全边界：本文不记录服务器、数据库或中间件密码；敏感运维信息仍仅按 `codex.md` 管理。

## 1. 一页结论

截至 2026-07-31，RAG 模块已经完成了不止一轮 Markdown 召回测试，而是覆盖了以下闭环：

1. SciFact 5,183 文档、300 问题的 Markdown 检索质量评测，四种检索变体共 1,200 条有效结果。
2. PDF、DOCX、Markdown 三格式的上传、解析、切块、Embedding、入库、检索、引用和页码验证。
3. PDF/DOCX 同源 200 份全策略对照，以及后续各 50 份的清洗与结构化切块消融实验。
4. Agent 与 Workflow 真实模型回答、引用集校验、无答案拒答、伪造引用拦截、SSE 与取消。
5. 知识库删除、MinIO 断连恢复、MySQL/Qdrant/MinIO 残留证据校验。
6. 并发 1/2 的稳定负载和并发 4 的边界失败试验，含远端容器资源采样。

核心结论：

- **质量上，Dense 是当前最稳的主检索基线。** SciFact Markdown 的 Dense Recall@10 为 `0.797944`，PDF/DOCX 200 份全策略均为 `0.960`，50 份消融集四个 run 均为 `1.000`。
- **Sparse 的主瓶颈是词汇错位。** 例如问题使用 `PPAR`、`Th17/iTregs`、`NF2/LATS`，金标证据使用 `RXR`、`TGF-β`、`LKB1/MARK`，纯词法检索无法稳定对齐。
- **RRF 不是无条件增益。** 它会将“Dense 强、Sparse 弱”的金标挤出候选池；在 SciFact 全量集上 Hybrid Recall@10 `0.750667`，低于 Dense `0.797944`。
- **Rerank 是确定的性能瓶颈。** SciFact 单线程平均端到端时延 `13,451 ms`；稳定压测中并发 1/2 的 rerank 平均时延为 `13,866/20,691 ms`，reranker CPU 峰值分别为 `518.03%/539.45%`。
- **PDF 解析明显慢于 DOCX，并已确认字符恢复缺口。** 同一正文中 DOCX 保留 `TGF-β`，PDF 子块变为 `TGF- `。
- **短摘要上过度结构化切块不划算。** 关闭结构化切块后，50 份 PDF/DOCX 子块分别减少 `40.9%/41.3%`，摄取均值下降 `21.1%/15.3%`；但这不能外推到长文、跨页表格或扫描 PDF。
- **系统目前的稳定并发边界是 2，不是 4。** 并发 4 在第 39 个正式样本出现 `67.19s` 的 fallback，按门禁判定失败。

## 2. 证据等级与统计口径

| 等级 | 定义 | 是否进入正式结论 |
|---|---|---|
| A | `status=completed`，样本数、唯一组合、错误/降级/空结果和 hash 均通过 | 是 |
| B | 已完成的功能或故障注入验收，但不用于泛化质量结论 | 仅用于对应功能结论 |
| C | 失败、`running`、早期修复轮次或探索性运行 | 否，只作故障留痕 |

指标口径：

- Recall@K：查询的金标文档在 TopK 中被找到的比例。
- MRR@10：第一个金标文档倒数排名的平均。
- nDCG@10：考虑排名位置的归一化增益。
- MAP@10：Top10 平均准确率。本批 PDF/DOCX 每问单金标，因此其数值与 MRR 一致。
- `success@K`：查询是否在 TopK 内命中任一金标。

**不报告的指标：** SciFact 及 PDF/DOCX 派生集没有自然语言最终答案金标；`gold.jsonl` 是证据文本而非模型答案。因此本文不编造 Faithfulness、Answer Correctness、ROUGE/BLEU 或幻觉率。Agent/Workflow 只用确定性关键词、引用集和包络校验，没有使用 LLM-as-judge。

## 13. 瓶颈优先级与可执行优化

### P0：Reranker 吞吐与候选池

证据：负载下 rerank 占端到端时间绝大部分，CPU 峰值超过 5 核；并发 4 首先出现 fallback。优化顺序：

1. 设置置信度跳过，Dense 或 Hybrid 头部 margin 足够时不 rerank。
2. fusion pool 和 rerank pool 解耦：先保留 20–30 候选，再选 6–8 个高价值候选重排。
3. 保留 Dense Top-N 最低配额和单路高置信保护，避免 RRF 把 Dense rank=1 金标挤出。
4. 在固定同源集上 A/B 更小模型、量化和服务端 dynamic batching，必须同时比较 R@10/MRR 与 p95。

### P1：PDF 解析与 Unicode 质量门禁

证据：PDF 摄取稳定慢于 DOCX，且已观测 `β` 丢失。需在 benchmark 中直接落盘 parser、IR 构建、artifact persist、embedding、vector upsert 分阶段 p50/p95，并增加 replacement character、断词连字符、页眉页脚重复、字形恢复检查。

### P1：按文档路由切块策略

单页、少于约 1,500–2,000 token、无表格/列表的文档可用粗块；多标题、长文、表格、列表、脚注保留 Document IR 和 parent-child。当 parent 与唯一 child 的 `content_hash` 相同时，可改为引用式 parent，减少 MySQL 冗余正文；当前 worker 只向量化 child，所以这不是 Qdrant 重复向量问题。

### P2：可观测诊断闭环

在可控 benchmark/debug 模式下持久化每路 raw rank/score、fusion score、rerank input/output 和被剪枝原因；生产默认仅记录 hash、排名和有限候选，避免日志与数据库膨胀。

## 14. 尚未被证明的能力

以下不是“已失败”，而是现有证据不足：

- 扫描型 PDF OCR、真实复杂表格、图片语义、多栏排版、脚注链接和跨页表格。
- 真实企业长文档上的跨节召回、parent expansion 收益和上下文拼接忠实度。
- 有自然语言标准答案的生成质量指标（Faithfulness、Answer Correctness、完整幻觉率）。
- 并发大于 2 的无降级稳定服务能力。
- 多租户大规模并发摄取、租户间资源抢占和长时间 soak test。

## 16. 最终判定
